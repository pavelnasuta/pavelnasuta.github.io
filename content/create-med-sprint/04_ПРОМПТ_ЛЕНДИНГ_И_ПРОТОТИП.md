# Промпт: лендинг и кликабельный прототип

Используйте после утверждения оффера и Карточки концепции v1. Этот промпт можно отправить в тот же Project.

Перед началом проверьте, что в Карточке концепции зафиксированы: трансформация пользователя, White space, главный тезис, reason to believe и ключевое возражение. Если какого-то поля нет, не придумывайте его в PROTOTYPE-чате: вернитесь в MASTER и заполните пробел.

## Шаг 1. Выбрать формат

```text
На основе утверждённой Карточки концепции предложи три формата демонстрации:
A) одностраничный лендинг с CTA;
B) кликабельный прототип из 3–5 экранов;
C) мини-инструмент, демонстрирующий одну ключевую функцию.

Для каждого в двух строках объясни: что зритель поймёт и чего этот формат не доказывает. Рекомендуй один вариант для нашей концепции. Не пиши код, пока я не выберу формат.
```

## Шаг 2. Сделать спецификацию

```text
Я выбираю формат [A/B/C].

Составь компактную спецификацию до 5 экранов/состояний: цель каждого, текст на экране, действие пользователя, реакция интерфейса. Используй только факты, утверждённые в Карточке концепции. Не используй фальшивые отзывы, логотипы, сертификаты, медицинские обещания и вымышленные цифры.

Проверь, что демонстрация разворачивает одно Ядро сообщения, а не набор типовых блоков:
- в первые 10 секунд видны главный тезис и трансформация «из → в»;
- пользователь видит, почему привычная альтернатива не закрывает выбранный сценарий (White space);
- механизм первой версии показан действием, а не абстрактным обещанием;
- есть reason to believe: источник, демонстрируемый механизм, релевантный контекст опыта команды или честно отмеченная гипотеза; опыт команды не выдаётся за доказательство результата;
- ключевое возражение не прячется: для него есть короткий честный ответ либо способ проверки.

После спецификации сформулируй `Визуальное направление` в пяти коротких пунктах:
1. аудитория и одно действие, которое должна вызвать страница;
2. эмоциональный тон, связанный с реальной ситуацией пользователя;
3. палитра из 4–6 цветов с ролями;
4. типографическая и композиционная логика на доступных системных шрифтах;
5. один характерный Hero-элемент, визуальная метафора или микроинтеракция.

Не используй общие слова «современно», «стильно» и «красиво». Не копируй универсальный AI SaaS-шаблон: тёмный градиент, одинаковые скруглённые карточки, три равные колонки, декоративные графики и эмодзи-иконки допустимы только если объясняются задачей продукта. Визуальное направление должно продолжать Ядро сообщения и сценарий, а не существовать отдельно от них.

После спецификации задай один вопрос: «Подтверждаем этот сценарий для кода?»
```

## Шаг 3. Сгенерировать локальный HTML

После подтверждения отправьте:

```text
Сгенерируй готовый демонстрационный файл `index.html` по утверждённой спецификации.

Технические требования:
- один самодостаточный HTML-файл: CSS внутри `<style>`, JavaScript внутри `<script>`;
- никаких внешних библиотек, CDN, API-ключей, запросов на сервер и сборки;
- файл должен открываться двойным кликом в современном браузере без интернета;
- адаптивный интерфейс для ширины от 360px;
- все интерактивные элементы должны работать: переходы между экранами, кнопка CTA, возврат назад, простая демонстрация сценария;
- используй семантический HTML, контрастный читаемый текст, видимые состояния фокуса, кнопки с понятными подписями;
- если нужны иллюстрации, используй простые встроенные SVG или CSS, не изображения из интернета;
- реализуй утверждённое Визуальное направление в единой дизайн-системе: CSS-переменные для палитры, осознанная типографика на системных шрифтах, ясная иерархия и один выразительный Hero-элемент или микроинтеракция;
- не подменяй смысл декором: не добавляй бессмысленные графики, иконки, облака слов, стоковые метафоры, фальшивые логотипы и одинаковые карточки ради «современного» вида;
- анимации используй только если они помогают понять сценарий; добавь поддержку `prefers-reduced-motion`;
- не добавляй формы, которые реально собирают личные или медицинские данные. Вместо этого по CTA показывай нейтральное подтверждение или переход к экрану «Заявка на пилот» без отправки данных;
- добавь внизу ненавязчивую подпись: «Демонстрационный прототип. Не является медицинской рекомендацией или работающим сервисом» — если концепция связана со здоровьем/медициной.

Перед кодом дай только 5 коротких пунктов: что в прототипе показано; главное сообщение; визуальное направление; выразительный элемент; как открыть файл. Затем выведи весь код в одном блоке `html`, без сокращений и без фраз «остальной код аналогичен».
```

## Как сохранить и показать

1. Скопируйте код из блока `html`.
2. Откройте редактор простого текста. На macOS в TextEdit выберите **Формат → Сделать обычным текстом**.
3. Вставьте код и сохраните файл под именем **`index.html`**. Важно: не `index.html.txt`.
4. Дважды кликните по файлу — он откроется в браузере.
5. Для показа на другом компьютере передайте только этот файл.

## Если нужен дизайн более высокого качества

После готового HTML можно попросить:

```text
Не меняя смысл, факты, CTA, Визуальное направление и интерактивную логику прототипа, улучши только визуальную иерархию: отступы, типографику, контраст, композицию, состояния кнопок и выразительность Hero-элемента. Не добавляй фальшивые изображения, цифры, отзывы, логотипы или новые обещания. Верни полный обновлённый `index.html`.
```

Не просите «сделать красиво» без ограничений: модель может заменить смысл и добавить вымышленные элементы.
