# Как устроить работу в ChatGPT Project

## Короткий ответ

Не нужно заранее заводить много чатов. Для одной живой демонстрации достаточно **одного Project**, одного основного чата и Perplexity в отдельной вкладке.

Если вы хотите получить ещё и код прототипа без путаницы, используйте в том же Project **два обязательных чата и необязательный третий**:

1. `00 — MASTER: концепция и решение` — проблема, Perplexity, факты, сегмент, оффер, контент лендинга. Это главный источник решений.
2. `01 — PROTOTYPE: HTML` — только спецификация интерфейса и код `index.html`.
3. `02 — PITCH: защита` — необязательный чат для тренировки презентации и вопросов жюри.

Perplexity не является чатом внутри Project: это отдельный исследовательский инструмент. Его результаты возвращаются в `00 — MASTER` целиком, со ссылками.

## Почему не один чат на всё

Для короткой демонстрации один чат работает. Но код в конце создаёт длинные сообщения, версии HTML и исправления — за ними теряются исходная проблема и принятые решения. Поэтому после того, как концепция утверждена, лучше создать отдельный чат для прототипа.

При этом **не надо полагаться на то, что новый чат идеально восстановит нужный контекст из памяти проекта**. Передавать нужно один короткий и утверждённый артефакт — «Карточку концепции v1». Это источник правды.

## Рекомендуемая схема

```text
Project: CREATE MED Sprint — [название кейса]
│
├── 00 — MASTER: концепция и решение
│   ├── Context: проблема и аудитория
│   ├── Perplexity: факты и альтернативы
│   ├── Offer/MVP: оффер, сегмент, CTA
│   └── КАРТОЧКА КОНЦЕПЦИИ v1  ← сохранить как project source
│
├── 01 — PROTOTYPE: HTML
│   └── получает карточку v1 → делает index.html
│
└── 02 — PITCH: защита (опционально)
    └── получает карточку v1 → делает питч и Q&A
```

## Пошагово: как вести одну демонстрацию

### 1. До занятия

1. Создайте **New project** в ChatGPT: `CREATE MED Sprint — Демонстрация`.
2. Откройте меню `•••` → **Project settings** → вставьте текст из `01_СИСТЕМНЫЙ_ПРОМПТ_CHATGPT.md` в **Project instructions**.
3. Создайте внутри него чат `00 — MASTER: концепция и решение`.
4. Откройте Perplexity в соседней вкладке.

Project instructions действуют только внутри этого Project и имеют приоритет над глобальными инструкциями ChatGPT. В Project можно хранить чаты, файлы и сохранённые ответы; это удобно, но не отменяет необходимость фиксировать ключевое решение в явном виде.

### 2. В основном чате

Напишите:

```text
Роль чата: MASTER.
Режим: живая демонстрация. Начинаем с поиска проблемы.
```

Дальше идите в одном чате по логике системного промпта:

- доведите до ясного `Problem Statement`;
- запустите нужные запросы в Perplexity;
- вставьте результаты поиска обратно в MASTER;
- выберите первый сегмент, оффер, CTA и формат демонстрации;
- попросите ChatGPT подготовить **Карточку концепции v1**.

Команда для последнего шага:

```text
Собери КАРТОЧКУ КОНЦЕПЦИИ v1 как единственный источник правды для следующего чата.
Используй строгий формат из Project instructions. Включи: Problem Statement; эмоциональную ставку и трансформацию; сегмент, пользователя и ЛПР/плательщика; факты с URL и применимостью; гипотезы и способ проверки; альтернативы и White space; JTBD; оффер, CTA и границы первой версии; reason to believe; Ядро сообщения и возражение; контентный каркас лендинга; сценарий и визуальное направление прототипа; открытые риски и следующий тест.
Не добавляй код, новые идеи или неподтверждённые факты. Неопределённое поле помечай «не определено» и переноси в открытые риски.
```

### 3. Зафиксировать карточку

У ответа с карточкой откройте меню сообщения и выберите **Save to project / Add to project sources** — название пункта может отличаться. Если такого пункта нет, скопируйте карточку в отдельный `.md`-файл и загрузите его в Sources проекта, либо просто сохраните текст для вставки в следующий чат.

Не сохраняйте в Sources каждую промежуточную мысль. Достаточно одной утверждённой версии карточки и, при необходимости, одного документа с источниками.

### 4. Сгенерировать прототип

Создайте чат `01 — PROTOTYPE: HTML` внутри того же Project. Первое сообщение:

```text
Роль чата: PROTOTYPE.
Работай только с КАРТОЧКОЙ КОНЦЕПЦИИ v1 из Sources проекта. Если она недоступна, попроси меня вставить её текст. Сначала проверь обязательные разделы; если есть пробелы, перечисли их и верни меня в MASTER, не додумывая их. Не возвращайся к поиску проблемы и не добавляй новых функций.

[ЕСЛИ НУЖНО — ВСТАВИТЬ КАРТОЧКУ КОНЦЕПЦИИ v1]
```

Затем используйте шаги из `04_ПРОМПТ_ЛЕНДИНГ_И_ПРОТОТИП.md`: сначала формат, затем схема экранов, только потом полный `index.html`.

Все доработки кода делайте **в этом же PROTOTYPE-чате**. Иначе модель может потерять текущую версию файла. Просите возвращать весь HTML, а не куски, если вы будете сохранять файл вручную.

### 5. Подготовить защиту

Если хватает времени, заведите `02 — PITCH: защита`. Первое сообщение:

```text
Роль чата: PITCH.
Используй только КАРТОЧКУ КОНЦЕПЦИИ v1. Сначала проверь обязательные разделы; при пробелах перечисли их и верни меня в MASTER, ничего не дополняя. Затем подготовь питч и будь строгим жюри. Не дополняй карточку новыми фактами.
```

Дальше используйте запросы из `05_ПИТЧ_И_ЗАЩИТА.md`.

## Какие запросы Perplexity использовать

Не нужно выполнять все пять.

| Ситуация | Что запускать |
|---|---|
| Обычная 2-часовая демонстрация | **№1**: масштаб/проявления проблемы + **№2**: текущие альтернативы. Этого достаточно. |
| Непонятно, как аудитория сама называет проблему или кто покупает | Добавить **№3**. |
| Решение заявляет медицинский эффект, диагностирует, влияет на лечение или работает с медицинскими данными | Добавить **№4** обязательно. |
| Несколько возможных первых аудиторий и нужно сузить фокус | Добавить **№5**. |

Ограничение: лучше два хороших запроса с понятными ссылками, чем пять обзорных ответов, которые никто не успеет проверить.

## Если есть загруженные материалы

- Есть презентация, заметки или описание проекта — загрузите их в Project Sources до начала либо прикрепите к MASTER-чату.
- В первом сообщении укажите: `Режим: из материалов. Используй только факты из загруженных файлов и помечай пробелы.`
- Загруженные файлы — это сырьё, а не автоматически верная версия. Утверждённой версией всё равно становится «Карточка концепции v1».
- В PROTOTYPE и PITCH не нужно загружать всё заново: передайте карточку v1.

## Самая короткая схема, если времени мало

Один Project → один MASTER-чат → Perplexity №1 и №2 → карточка v1 → в этом же чате запрос на `index.html` → 60-секундный питч.

Это менее аккуратно, но работает за 60–75 минут. Схема с отдельным PROTOTYPE-чатом лучше для полноценного занятия на два часа.

## Что реально умеет Project

По официальной справке OpenAI, Project объединяет инструкции, файлы и связанные чаты; в него можно сохранять ответы как Sources. Инструкции Project действуют только внутри него. ChatGPT может использовать проектный контекст, но для критичных решений опирайтесь на явную карточку v1, а не на предположение, что модель вспомнит прежние формулировки.
