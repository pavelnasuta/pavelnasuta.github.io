# Telegram Channel Analytics: дизайн

## Цель

Выпустить публичный skill `telegram-channel-analytics` для автора Telegram-канала, которому нужен еженедельный редакционный отчёт на основе фактически доступных данных. Навык создаёт накопительную историю собственных публикаций, повторно измеряет «живые» посты, собирает месячные и годовые сравнения из сохранённых снимков и, при явном выборе автора, добавляет сопоставление с тематически похожими каналами.

## Границы релиза 1.0

- Skill read-only: он не публикует посты, не меняет канал и не создаёт Telegram-сессии.
- Релиз использует только открытые данные постов и локально сохранённые снимки. Для публичного канала это могут быть дата публикации, ссылка/ID поста, текстовый формат, просмотры и публично видимые реакции.
- Администраторские права бота — отдельный будущий контур. Bot API может подтверждать идентичность канала и доступные базовые сведения, но не считается доступом к нативной Telegram-аналитике, источникам трафика, аудитории или репостам.
- Сравнительный контур работает только с объявленным watchlist из похожих публичных каналов. Он не строит рейтинг, не выдаёт причинные выводы и не делает скрытого сбора данных.
- Исходные снимки append-only: новый замер добавляется, старый не перезаписывается. Изменение источника или методики начинает отдельный ряд.
- Публичный пакет не содержит реальных каналов, метрик, токенов, ключей, сессий, абсолютных локальных путей, приватных редакционных материалов или персональных настроек.

## Пользовательский результат

Каждый запуск формирует один недельный редакционный отчёт с пятью явными блоками:

1. период, источники и полнота данных;
2. факты по опубликованным и повторно измеренным постам;
3. динамика относительно предыдущего сопоставимого среза;
4. до двух проверяемых редакционных гипотез;
5. неизвестное, пробелы и ограничения.

При накоплении данных skill строит месячную сводку из сохранённых недельных и постовых снимков, а годовое сравнение — только из сохранённых месячных сводок. Он не пытается реконструировать прошлое повторным чтением ленты.

## Модель данных

Пользователь выбирает каталог проекта при первом запуске. В нём skill ведёт:

- `project.json`: название проекта, часовой пояс, ссылка на основной канал, политика измерений, методика и дата её версии;
- `snapshots/posts/`: неизменяемые JSON-снимки каждого доступного постового измерения;
- `snapshots/channel/`: неизменяемые JSON-снимки уровня канала, если они доступны и источник назван;
- `watchlists/`: версии списка сравнения с причиной включения, тематикой, языком, диапазоном размера и форматами публикаций;
- `reports/weekly/`, `reports/monthly/`, `reports/yearly/`: отчёты и их manifest с входными снимками;
- `methodology/`: журнал изменения источников, расчётов и рядов сопоставимости.

У каждого снимка обязательны время сбора, источник, метод, идентификатор поста/канала, доступные значения, отсутствующие значения и версия методики. Производные документы ссылаются на точный список использованных снимков.

## Измерение живых публикаций

Для нового поста skill планирует замеры сразу после появления в доступном источнике, через 24 часа, 7 дней, 14 дней и затем при закрытии каждого месяца, пока пост входит в период анализа. Поздний рост от рекламы или репостов фиксируется как наблюдаемое изменение между снимками, а не приписывается конкретному источнику без подтверждения.

Недельный отчёт показывает текущий измеренный срез. Он не называет итоговым значение поста, который ещё находится в окне повторных измерений.

## Сравнительная аналитика

Watchlist задаётся автором до первого сравнения. Для каждого канала указываются тема, язык, размерный диапазон, обычные форматы и причина сопоставимости. В сравнении:

- нормализуются возраст поста и, если честно доступно, масштаб канала;
- не смешиваются каналы с разными языками, темами, форматами или существенно иной аудиторией без явной пометки;
- показываются различия ритма, формата и доступных постовых сигналов;
- все интерпретации маркируются как гипотезы, а не доказательство причины;
- состав watchlist и время каждого замера входят в отчёт, поэтому сравнения сохраняют воспроизводимость.

## Интерактивный контракт

В начале нового проекта skill спрашивает только отсутствующие существенные параметры: основной канал, часовой пояс, период отчёта, источник, место хранения и нужен ли watchlist. Конфигурация сохраняется в `project.json` только для этого проекта; другой канал не наследует настройки автоматически.

Если данные недоступны, навык не предлагает обход через пользовательскую Telegram-сессию. Он фиксирует недоступность и объясняет, какой подтверждённый источник нужен для расширения среза. Регулярный запуск настраивается только отдельным явным запросом автора; публикация отчёта в Telegram не является частью навыка.

## Проверки

До публикации обязательны:

1. тесты сначала падают при отсутствии требуемого контракта, затем проходят после его создания;
2. валидатор принимает корректный synthetic project и отклоняет отсутствующий источник, перезапись старого снимка, несвязанный отчёт и сравнение без зафиксированного watchlist;
3. scan публичных файлов не находит токены, сессии, абсолютные локальные пути, реальные Telegram-каналы и закрытые материалы;
4. README и adapters указывают на один канонический workflow;
5. сайт содержит публичную registry-запись, русскую страницу навыка, отдельный 1200×630 JPEG, canonical/OG/Twitter/JSON-LD, sitemap и карточку Hub;
6. локальные site tests, HTML/JSON-LD checks, desktop/mobile проверка и live-проверка кастомного домена подтверждают публикацию.

## Сайт

Страница `/skills/telegram-channel-analytics/` объясняет назначение, реальные сценарии, накопительную модель, повторные измерения, сравнительный контур, ограничения источников, установку и ссылку на GitHub. Карточка Skill Hub ведёт на эту страницу, а не напрямую в репозиторий.

OG-визуал: временная шкала постов, где поздние измерения добавляют реальные точки к уже зафиксированной истории; рядом отдельный, маркированный контур сравнения, без рейтинга и ложной точности. Изображение — самостоятельный JPEG `og-skill-telegram-channel-analytics.jpg`, 1200×630.

## Не входит в 1.0

- подключение личного Telegram-аккаунта, MTProto, `api_id`, `api_hash`, session files или автоматический доступ к Telegram Statistics;
- скрытый скрейпинг, автопостинг, бот-команды, автоматическая рассылка отчётов;
- прогнозирование, оценка качества текста как факта, причинные выводы о рекламе/репостах;
- сравнение с каналами, не внесёнными в явный watchlist;
- реальные данные и примеры пользователя в публичном репозитории или на сайте.
