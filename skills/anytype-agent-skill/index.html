Не импортёр файлов, а рабочая модель пространства

Anytype легко превратить в плоский набор страниц, ссылок и несогласованных тегов. Этот skill задаёт агенту другой порядок: сначала понять существующую систему, затем выбрать правильную сущность и только после этого делать минимальное проверяемое изменение.

НА ВХОДЕСуществующее Space, страницы, материалы, Types, Properties, теги и навигация.
НА ВЫХОДЕСвязная структура: нативные карточки, управляемые свойства, понятные даты и отношения без копий.
ПРИНЦИПНикаких предположений о возможностях API и никаких заявлений об изменении без точного read-back.

Сценарии

Навык полезен при импорте материалов, перестройке навигации, создании повторяемых типов, поиске дублей и работе с живой базой, где параллельно могут редактировать люди. Он помогает не путать Page, Type, Property, Query и Collection — и не превращать дату, статус или теги в текст внутри заголовка.

Быстрый старт

Клонируйте репозиторий и запускайте совместимый агент из его корня. Он найдёт правила в адаптере для своей среды; для Hermes, Claude Code, Codex и AGENTS.md-совместимых агентов предусмотрен один общий операционный контракт.

git clone https://github.com/pavelnasuta/anytype-agent-skill
cd anytype-agent-skill
# запустите ваш AI-агент из этой папки

Перед первой записью агент должен подтвердить целевой Space, прочитать существующую модель и проверить доступные API-возможности.

Подключение к AI-агенту

В основе — один canonical skill и тонкие адаптеры: Hermes использует нативный SKILL.md, Claude Code и Codex — свои проектные инструкции, а другие среды могут читать AGENTS.md. Это не означает, что каждый UI-элемент Anytype автоматически доступен через любой Local API.

Hermes

Проверенный сценарий: Local API, структура Space, read-back и безопасная автоматизация.

Claude Code и Codex

Совместимые адаптеры указывают на тот же набор правил, а не копируют методику.

AGENTS.md-совместимые среды

Могут использовать переносимый контракт на уровне проекта или рабочего каталога.

Как устроена работа

  1. Discover: агент читает Space, Types, Properties, страницы, права и реальные возможности API.
  2. Search: при доступности начинает с полнотекстового поиска; semantic поиск использует только когда он действительно поддержан и нужен по смыслу запроса.
  3. Snapshot: перед записью фиксирует разрешённые свойства, options и существующий образец, чтобы не плодить дубли.
  4. Change: меняет минимальный уникально определённый блок, использует concurrency guard при доступности и не перезаписывает длинную Page ради одного абзаца.
  5. Verify: читает целевой Object обратно и сообщает только подтверждённый результат.

Границы важнее скорости

Skill не переносит пароли, recovery phrases, ключи, токены, credential-файлы и системные логи. Он не удаляет, не архивирует, не меняет права и не перестраивает модель массово без отдельного явного согласования.

Если нужной функции нет в подтверждённом API, агент называет ограничение и предлагает минимальный ручной шаг в Anytype — не имитирует выполненную работу.
